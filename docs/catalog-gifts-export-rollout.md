# تغییرات کاتالوگ، پاداش، روز هدیه و خروجی اضطراری کاربران — ۲۰۲۶-۱۰-۱۷

این فایل همراه سورس کامل است. **این تغییرات روی سرور شما اجرا نشده‌اند.** ابتدا روی staging با کپی امن داده‌ها آزمایش کنید.

## خلاصه تغییرات

1. **آرشیو و نمایش:** درخواست Connectix فقط `is_archived=false` می‌گیرد و حتی اگر endpoint اشتباهاً `is_archived=true` برگرداند، آن پلن کنار گذاشته می‌شود. پلن‌های حذف‌شده از پاسخ پنل با `is_active=false` در دیتابیس محلی غیرفعال می‌شوند. `is_displayed_in_robot=false` نیز فروش را غیرفعال می‌کند. غیرفعالی و `is_visible=false` در تمام فهرست‌ها رعایت می‌شود؛ callback قدیمی هم مجاز به خرید پلن غیرفعال نیست. تنظیم نمایش محلی (`sync_bot_settings=False`) در همگام‌سازی حفظ می‌شود.
2. **ترتیب:** در فهرست‌ها اول `display_order` ادمین، سپس شناسه پلن ملاک است. بازه‌ها برای کاربر طبق حجم مرتب هستند اما *داخل* بازه، پلن‌ها طبق ترتیب ادمین نشان داده می‌شوند. در صفحه تمدید، طرح فعلی عمداً به ابتدای فهرست می‌رود. گزینه نامحدود مقایسه‌ای، در انتهای بازه پُرحجم (یا صفحه اول، اگر لیست طولانی باشد) اضافه می‌شود.
3. **نامحدود مقایسه‌ای:** انتخاب بالاترین بازه حجم *موجود*، پلن(های) نامحدود همان برند، سرویس، مدت و تعدادکاربر را نیز اضافه می‌کند؛ قیمت‌ها از دیتابیس خوانده می‌شوند. هیچ پلن مجازی تولید نشده است.
4. **روز هدیه:** فیلد `gift_days` و Migration اضافه شده‌اند. اسامی پنل مثل `+3d` / `+5d` / `+10d` به `+۳روز هدیه` و ... تبدیل می‌شوند. پلن‌های Connectix این مقدار را از نام پلن بالادستی همگام می‌کنند؛ نام آن برای پلن‌های محلی نیز قابل استفاده است. **این تغییر به‌تنهایی مدت سرویس واقعی را افزایش نمی‌دهد**؛ فرض بر این است که روزهای هدیه از پیش در سرویس‌دهنده لحاظ شده‌اند. اجرای واقعی هدیه باید روی اشتراک تحویل‌شده در Connectix تست شود.
5. **امتیاز:** همهٔ خریدهای اشتراک `plan_type=unlimited` و `service_category=royal` بدون توجه به مدت، تعدادکاربر یا نوع خرید، نرخ **۴٪** برای ارزش نقدی پاداش معرفی دارند؛ مسیر عادی، چالش و هدیه بررسی و یکسان‌سازی شده‌اند. نرخ سایر پلن‌ها مطابق قوانین موجود باقی است. پرداخت جایزه همچنان مشروط به اعتبار خرید و سایر قوانین امتیاز است.
6. **محدودیت موقت ۲/۳ ماه:** با تنظیم محیطی `TEMP_DISABLE_2_3_MONTH_PLANS=True` پلن‌های ۲ و ۳ ماهه (و معادل‌های دقیق ۶۰/۹۰ روز یا ۸/۱۲ هفته) در صفحه‌های فهرست با 🔴 نشان داده می‌شوند و درخواست انتخاب پیام «زمان درخواستی موقتاً غیرفعال است» می‌گیرد. خرید مستقیم، تمدید، خرید برای دیگری و جریان پرداخت سفارش بازِ قبلی نیز نمی‌توانند این ممنوعیت را دور بزنند. وضعیت و قیمت پلن در پنل ادمین حذف یا تغییر داده نمی‌شود.
7. **خروجی Excel:** در `Admin → Accounts → Users` فیلتر «اشتراک معتبر در حال حاضر» و «نوع سرویس فعال» اضافه شده؛ دکمه «خروجی اکسل کاربران با فیلتر فعلی» تمام نتایج جستجو و فیلتر اعمال‌شده را دانلود می‌کند. اکشن «خروجی Excel کاربران انتخاب‌شده» نیز برای سطرهای انتخابی وجود دارد. فایل XLSX دارای فیلتر ستونی، سطر عنوان ثابت، فرمت متنی شماره تلفن و شناسه تلگرام است. فقط مشتریان (`user_type=customer`) خروجی می‌شوند، نه حساب‌های مدیریتی.

### تعریف اشتراک فعال

`Subscription.owner` صاحب واقعی اشتراک است (نه لزوماً پرداخت‌کنندهٔ اشتراک هدیه). یک اشتراک زمانی «فعال» محسوب می‌شود که `status=active` و `expires_at` خالی یا در آینده باشد. کاربران با اشتراک منقضی، حتی اگر status قبلاً به‌روز نشده باشد، «بدون اشتراک فعال» محسوب می‌شوند. «نوع سرویس فعال» فقط روی اشتراک‌های معتبر فعلی اعمال می‌شود.

### زمان همگام‌سازی

همگام‌سازی خودکار پنل Connectix از قبل هر **۹۰۰ ثانیه (۱۵ دقیقه)** در Celery Beat تنظیم شده؛ تغییر آرشیو در پنل بالادستی تا اجرای همگام‌سازی بعدی در دیتابیس محلی دیده نمی‌شود. تغییرات `is_active`/`is_visible` در Django Admin بعد از commit کش را باطل می‌کنند؛ endpoint فروش هم پلن را دوباره از DB اعتبارسنجی می‌کند.

برای اعمال فوری پس از ویرایش‌های پنل Connectix، در **Django Admin → VPN Providers** سرویس موردنظر را انتخاب و اکشن `Sync Connectix plans` را اجرا کنید. Celery worker باید فعال باشد. اجرای sync جدید پلن‌های آرشیوشده را از دیتابیس پاک نمی‌کند؛ آن‌ها `is_active=false` می‌شوند تا سفارش‌های قدیمی پابرجا بمانند.

## استقرار توصیه‌شده

**۱.** از دیتابیس PostgreSQL، فایل‌های media، فایل `.env` و نسخه اجرای فعلی بکاپ بگیرید. به‌دلیل وجود اطلاعات کاربران و تراکنش‌ها، فایل بکاپ باید در مسیر امن ذخیره شود.

**۲.** این کد را در staging با نسخه‌های مشخص موجود در `pyproject.toml` و `uv.lock` نصب کنید. پروژه در حال حاضر `requires-python >=3.14` دارد.

```bash
uv sync --frozen
uv run python manage.py check
uv run python manage.py makemigrations --check --dry-run
uv run python manage.py migrate --plan
uv run python manage.py migrate
```

**۳.** تست‌ها را اجرا کنید:

```bash
uv run python manage.py test \
  apps.bot.test_plan_picker \
  apps.accounts.test_emergency_export \
  apps.referrals.tests \
  apps.orders.tests \
  apps.bot.tests
```

**۴.** با دیتابیس staging، تأثیر آرشیو پلن، ترتیب هر دو سرویس، هدیه +3d و +10d، خرید نامحدود رویالِ ۱ تا ۴ کاربر، و بلاک‌شدن مسیرهای ۲/۳ ماهه را دستی آزمایش کنید. مقدار امتیاز نهایی پس از پرداخت و تکمیل چالش باید ۴٪ باشد (نه فقط عدد UI).

**۵.** پنل ادمین را با حساب brand manager هم تست کنید؛ او باید بتواند فقط کاربران برندهای مجاز را ببیند/خروجی بگیرد. فایل XLSX دانلودی شامل اطلاعات شخصی است؛ آن را در فضای عمومی قرار ندهید.

**۶.** Deployment را با rolling restart سرویس‌های `web`, `bot`, `worker`, `beat` انجام دهید. بعد از sync موفق پنل، از یک حساب تلگرامی آزمایشی همان برند وارد خرید و تمدید شوید.

**۷.** هنگامی که تمام پلن‌های ۲ و ۳ ماهه تکمیل شدند، فقط در صورت تأیید تیم فروش و پس از تست مجدد، `TEMP_DISABLE_2_3_MONTH_PLANS=False` را در تنظیمات سرویس Bot/Backend قرار دهید و پروسه‌ها را reload کنید.

## محدودیت‌های اعتبارسنجی این بسته

- تست نحو Python و ساختار XLSX با ابزارهای محلی انجام شده‌اند.
- تست end-to-end Django/aiogram در این محیط اجرا نشده است (وابستگی‌های Django، aiogram و Python 3.14 در محیط حاضر نصب نیستند). **نباید این بسته را بدون `manage.py check`، مهاجرت آزمایشی و تست روی دیتابیس staging، production-ready قطعی دانست.**
- داده‌ها و وضعیت واقعی Connectix در دسترس نبودند؛ نمی‌توان با قطعیت گفت تمام پلن‌های کنونی شما چه روزهای هدیه، قیمت، محدودیت یا ترتیب دارند.
- هیچ شماره کارت، API Key، توکن ربات یا آدرس شخصی به این تغییرات اضافه نشده است.
